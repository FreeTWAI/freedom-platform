# 自由工坊共同參與與合作模式設計

2026 年 10 月 20 日設計草案，供 Hao 與 Ted 審閱。

## 本 PR 實作範圍

本 PR 從 main@1f866fb8 實作第一個可獨立驗收的入口增量：

- 首頁提供技能與工具、社群活動、合作夥伴與作品交流四個原頁入口；860px 以下預設收合在「一起學、一起做」，合作摘要一併按需展開，保留建立貼文的首屏位置。桌面維持展開。
- 原公會學習、技能書與本人未完成工作移到動態前，手機不用先展開「我的工坊」。原動態與發文器直接保留。
- 以 GET /api/v1/engagements/summary 讀本人兩個布林事實，顯示合作是否有後續步驟；確認、交付、收款回報仍在既有合作頁。
- 本人內容能力開啟時提供草稿／發布狀態原入口；讀取失敗可單獨重試，離頁與登入世代改變會取消過期回應。

以下完整模式是供審核的分期提案。主理人授權、一般參與的 onboarding 邊界、官方支援及收益分配等後續項目仍依各節列出的條件處理。本次不宣稱已完成整套模式、營運試辦或留存成效。


自由工坊的共同主張建議定為：每個人都能先一起玩、一起學，再按自己的需要做作品、找夥伴與經營收入。持續留下來的理由，來自有人認識自己、共同完成事情，以及累積可繼續使用的成果。

一般相關分享與互推開放，是 Hao 已確認的方向；費率、收益分配權重、付費課程介紹邊界、曝光配額與主理人授權細節仍待定。以下未列入本 PR 實作範圍的狀態名稱與新增欄位仍是設計建議；本次產品修改限上方入口與摘要，不修改正式制度。

## 一 共同目標與留存

### 把共識寫成社員能參與的事

平台入口與每個公會使用同一段簡短說明，並連到當期真實活動與工作：

> 沒有作品、技能或資源，也歡迎一起玩、一起學。
>
> 分享自己正在做的事，幫彼此把想法變成成果。
>
> 歡迎發展自己的品牌與社群，尊重作者與夥伴，說好的合作一起完成。
>
> 可以提問、批評與不同意；騷擾、冒用身分和反覆洗版會依規則處理。

這段內容用於理解社群。閱讀次數、口號背誦或認同測驗不成為加入與分享門檻。實際行為規範另以易懂的條款呈現。

每個公會只維護一個「這一期一起做什麼」區塊，包含目標、主理窗口、可參與方式、下一次聚會與成果入口。時間與活動必須來自已安排的內容；尚未安排時直接顯示尚未安排。沿用公會公告、發布設定、既有小隊和作品來源，不另開一套公會任務引擎。

### 回應創辦人的四個顧慮

| 顧慮 | 具體安排 | 留在自由工坊的價值 |
| --- | --- | --- |
| 有能力的人逐漸離開 | 邀請自願投入的人主理一個範圍清楚的專題，給排程、內容與小隊的實際決定空間 | 熟悉的夥伴、可持續主理的空間、能被接上的資源 |
| 平台協助對方成長後不再合作 | 官方支援逐案記錄這一期投入、交付、使用範圍及結束安排；下一期另議 | 當期已完成的成果、可追溯的署名與合作紀錄 |
| 大社群變成單向導流入口 | 一般推廣開放；重複促銷、無關洗版、批量私訊依可辨識行為處理；精選支援另外排程 | 可交流的內容品質、可找到人的合作場域 |
| 人多但共識薄弱 | 公會提出可參與的小目標，固定交流成果和卡點，讓社員經歷多次一起完成事情 | 共同經驗與持續的合作關係 |

這些安排能控制單次投入，無法保證成員永遠留下。停止額外合作時，結清既有義務並完成交接；正常會員權益和已認列成果仍依原規則保留。

### 三種參與方式

| 參與方式 | 能得到什麼 | 可開始的動作 |
| --- | --- | --- |
| 玩樂與學習 | 認識人、體驗工具、完成一個小練習 | 看活動、閱讀技能介紹、提問、參加學習或玩樂小隊 |
| 分享與互助 | 展示作品、得到回饋、發展自己的品牌與社群 | 分享作品或連結、回答問題、提出想找的資源 |
| 合作與經營 | 找專長、做共同專案、依約取得報酬或販售商品 | 提出需求、確認合作、開店或供貨、交付及回報收款 |

這是同一會員可自由使用的不同入口。同一人可以同時是學習者、創作者、供應商、開發者與主理人，不建立互斥角色，也不按商業價值把社員分等。

### 各方持續使用的價值

| 角色 | 能帶來的參與 | 平台應幫他得到的價值 |
| --- | --- | --- |
| 學習者與探索者 | 問題、學習過程、體驗回饋，也可以先旁觀 | 容易理解的起點、能跟做的內容、認識夥伴的機會 |
| 供應商 | 商品、產品知識、供貨與履約資訊 | 適合的推廣夥伴、清楚的合作條件與訂單可見範圍 |
| 創作者 | 內容、作品、使用情境與推廣能力 | 可用工具、適合合作的品牌與依約成立的製作報酬或佣金 |
| 開發者 | 工具、數位產品、維護與技術協助 | 真實使用者、測試回饋、共同開發與付費合作機會 |
| 公會與獨立社群主理人 | 交流、活動、接待與專題共作 | 保留品牌、可決定的主理範圍、互補資源和有署名的成果 |
| 平台營運者 | 入口、協調、媒合、共同資源與必要管理 | 可追溯的當期成果、可接續的合作關係，以及有效約定下的服務收入 |

## 三 頁面與入口設計

### 日常入口

沿既有導航整理成容易辨認的日常用途，保持更多功能與管理分組：

- 首頁：當期一起做的事、原入口內容、本人待回覆與未完成工作。
- 探索：技能與工具、活動與小隊、作品與需求、商品與服務，使用原本各頁與搜尋。
- 我的事：原「我的內容」「我的工作」「合作紀錄」的入口彙整，資料仍由原模組管理。
- 訊息：原通知、私訊、公會及小隊聊天。

這是導航分組建議，不新增四套資料庫，也不要求把既有網址換掉。舊分享網址與瀏覽器返回要繼續可用。

### 首頁草圖

```text
自由工坊                                   訊息  帳號
一起玩、一起學，也把想做的事做出來

[找技能與工具] [看活動與小隊] [找合作] [分享我的事]

從技能書連結進來：接回那本書和可開始的動作
已參與的人：先顯示需回覆的合作、原草稿與下一個具體動作

這一期一起做什麼
原公會公告／小隊目標 + 主理窗口 + 真實活動 + 參與入口

大家正在分享
作品、學習過程、資源與外部社群；保留作者和來源
```

不加一道必答的「你是哪種人」問卷。首頁動作直接打開原頁；目標偏好可以自願記住並隨時更換。新手即使先逛逛、參加玩樂小隊，也是一條完整入口。

手機優先保留建立貼文、公會學習與本人未完成工作；四個參與入口與合作摘要沿用首頁收合模式按需展開。次要說明按需展開；失敗的資料區塊可單獨重試，其他入口仍可使用。載入態、真正空清單、功能未啟用、沒有權限須有各自的說明。


一般分享維持精簡。作品、服務等專用資料，仍在原編輯器管理；不因聚合入口就把商品條件、私人報價搬進一般貼文。

發布者自己的品牌、原作者和外部社群來源清楚呈現。「官方合作」標示只根據目前有效的合作範圍產生；作者不能靠勾選自行取得。付費課程介紹邊界留待決策，不能因新增入口就默認全部准許。

## 四 五條使用流程

### 新人與探索者

1. 外部技能、活動或作品連結打開原內容，先了解用途。
2. 可以看內容、找活動或試一個練習。想儲存、發問或參與時，再沿相應登入入口處理。
3. 註冊與既有帳號登入後，都安全返回原內容；內容已撤回時說明原因並提供同主題入口。
4. 建議增加有界的「已註冊、尚未選公會」基本參與範圍，讓公開交流不依賴職業定位。公會聊天、技能領取和商務／tenant 工作仍使用原准入與授權。
5. 自願選公會或加入小隊，看看當期在做的事；接待有人力時可自願請求協助。

第 4 點是產品與權限調整。實作須逐 API 列出允許行為和負向案例，不能刪掉全域 onboarding 檢查、代填完成時間或替人自動加入公會。若這一階段尚未完成，就先保留真實預覽範圍，不顯示無法操作的發問或加入按鈕。

### 一般分享與互推

直接從分享入口介紹作品、工具、服務或自己的社群，選擇可見範圍並預覽發布。有人感興趣可回覆、查看名片或自願聯絡；不必建立官方合作，不要求交換名單或回流配額。

外部連結仍遵循技術上的安全格式檢查、目前身分與內容可見規則。這些檢查不把「外部網址」「第一次發文」或「零貢獻」當成廣告違規。

### 找夥伴與合作媒合

現有「看作品 → 向作者提出需求 → 作者提案 → 雙方合作」繼續可用。

新增的公開徵人流程應是：需求草稿 → 明確公開 → 收到合作意願 → 選擇一起洽談的人 → 雙方確認範圍與條件 → 交付與接受 → 經同意公開成果。

公開需求至少說明要完成什麼、找什麼協助，以及報酬形式是自願、固定費用、佣金或待討論。日期、預算與參考作品可選填；未知金額就顯示待討論。

目前 opportunities 將作品與提供者綁定，不能只把作品 ID 改成選填就視為完成公開媒合。建議在同一 opportunity-project-work 模組增加公開需求的薄層；當需求方選擇洽談對象時，才建立對應的私下提案關係。資料遷移與既有協議關聯交由實作切片審查，不偽造作品來滿足既有外鍵。

### 夥伴社群

先用一般分享介紹外部社群，保留自己的名稱、入口與主理人。想共同辦活動或需要額外支援時，才記錄這一案的目的、窗口、投入與期間。共用活動仍沿現有活動與小隊能力；到期後整理成果與交接，不要求交出社群控制權。

### 核心主理人

由願意持續主理的人提出當期小目標、能提供的時間與需要的平台支援。在既有公會／小隊授權內安排內容、接待、活動與成果整理；實際可決定事項寫清楚，與稱號分開。

主理人可提出精選安排或費用需求；資源與結算仍由相應有權者確認。公會內容編輯權不擴張成全站管理、讀取私人工作或付款權。交接時轉移原小隊或內容責任，保存署名與有效歷史，撤銷舊的未來操作權。

## 五 分享規則與官方投入

### 一般規則

一般相關內容、首次自薦與外部社群互推預設開放，不設粉絲、活躍、免費工作或排行榜門檻。期望交流以行為規則說明，不用猜測作者內心的「忠誠度」當作處罰依據。

處理重複促銷、與社群無關的廣告、持續單向招生、批量私訊、冒用官方及騷擾時，先指出具體內容與行為。單有網址、售價、課程字眼或批評平台，不構成自動違規。付費課程單次介紹是否允許、應有哪些條件，保持待定。

分享外部活動連結適用一般分享；要求平台行事曆收錄、報名或官方共同主辦時，適用相應流程。兩者的審核範圍需要在入口說清楚。

### 官方投入按案安排

| 展示說明 | 適用情況 | 要記錄的範圍 |
| --- | --- | --- |
| 社員自行分享 | 本人公開介紹作品、服務或社群 | 作者、來源、分享內容與可見範圍 |
| 平台協助推廣 | 額外精選位置、活動介紹、媒合或協調 | 協助項目、窗口、素材、期間與當期成果 |
| 共同專案 | 雙方實際投入製作、開發或共同主辦 | 分工、交付、驗收、報酬條件、品牌使用、結束與交接 |

標示描述這一次作品或專案的關係，不是會員永久等級。沒有平台額外投入的獨立收入，不因社員身分自動抽成。

每次額外支援只承諾目前可提供的部分。後續支援看當期成果與人力，再另定安排。品牌使用與成果使用權按案確認，不以加入社群換取所有未來作品的權利。

### 管理與異議

延伸既有 member_reports 和 transition_journal：處置附內容依據、規則版本、理由、作用範圍與時間，通知受到處置的人可理解的摘要；私人證據及檢舉者身分不直接公開。

先採可連回原案件的輕量異議入口。涉及原處理者自身利益時，交由另一位有權者覆核；能否安排第二位處理者與回應時間必須依人力確認。錯誤處置保留更正紀錄，復原前仍檢查內容與媒體可讀性。

頻率控制使用可配置的重複內容和速率限制，明確提示重試或修正方式；數值待營運試辦後決定。AI 可以整理內容，管理決定保留具體依據，不把負面語氣或不同意管理者自動轉成違規。

## 六 資料狀態與權限

### 各類事實分開

| 資料 | 現況或建議狀態 | 權限與界線 |
| --- | --- | --- |
| 一般分享 | 原模組的草稿、發布、撤回或隱藏 | 作者管理自己的內容；讀者按目前可見範圍讀取；管理處置須有權限 |
| 公開需求 | 建議草稿、徵求中、暫停、結束、撤回 | 發起者維護；應徵或提出意願不等於已接受合作；私人洽談對象不全數公開 |
| 商業合作 | 現有 proposed → agreed → delivered → accepted | 提供者提案與交付，需求方同意與接受；修改條件、補件、取消及爭議需另加有界轉移 |
| 自願工作 | 現有 claimed → in_progress → submitted → in_review → accepted／changes_requested | 申請者不能驗收自己；有效驗收安排與提交內容雜湊需匹配 |
| 收款回報 | 現有 self_reported → counterparty_confirmed | 提供者回報、另一方確認；不顯示為銀行核實 |
| 佣金與付款 | 建議待計算、待確認、應付、已支付、調整／退款 | 僅有效條件才可計算；已支付須有相應付款證據，不能由點擊推導 |
| 貢獻 | 原已驗收 contributions；其他貢獻類型待設計 | 留來源、驗收者、時間和更正歷史；不自動增加永久分紅權 |
| 官方支援 | 建議草擬、確認、進行、完成、到期或終止 | 雙方窗口確認範圍；只有適當權限可承諾平台資源或品牌 |
| 平台分配期間 | 建議草案、規則生效、核對、確認、支付及調整 | 只處理平台自己的收入；規則、成本、批准者與付款依據各自保存 |

這些狀態跨不同資料來源，不合成一個「總完成百分比」。合作被接受可顯示交付完成，收款仍按自己的證據呈現；平台協助到期也不回寫已驗收工作為未完成。

### 最小必要欄位

- 一般分享沿既有作者、內容、來源、受眾與公開同意，不強制建正式合作資料。
- 需求補主題、需要的協助、報酬形式、目前是否徵求與可選期限，連回原作品或活動時保留來源。
- 合作沿用當事人、scope、acceptance_criteria、terms_sha256 與 aggregate_version。新的條件修訂先提出版本，再取得相關人同意；接受前後都保留有效歷史。
- 官方支援只補相關合作、雙方窗口、投入、期間、品牌範圍、交付與交接。先評估原合作模組可承接的擴充，不另做通用審批引擎。
- 公開合作履歷只從本人與必要參與者同意的欄位投影；預設不帶私人價格、憑證、登入信箱與對話。

### 兩層收益

單一交易先按有效約定處理商品／服務提供者、推廣者、實際工作者與平台服務費，退款和必要費用亦依該約定調整。這一層使用真正應收、實收回報與付款的不同紀錄。

平台貢獻分配另從平台自己的收入出發，扣除已核准類型的成本與保留安排後，再按有效期間的規則計算。供應商貨款與創作者應收佣金不再混入平台分配池。

目前不設定費率、權重、成本扣除範圍、結算週期或提款承諾。制度生效前只呈現貢獻與已確認的合作事實。開源程式與既有免費交流維持原使用條件，平台提供的額外服務按案說明。

1. 把公會本期目標、固定成果交流和可參加小隊放到原入口；沿用已發布設定，保留主理人決定空間。

4. 合作條件修訂、補件、取消與爭議分別收斂；成果經同意再公開。

### P2 依真實交易完善收益

1. 固定費用、佣金與退款條件版本化，將應付與實付分開。
2. 再依已定案的營運、費率和支付方式補核實與付款旅程；checkout OFF 期間維持明確的展示與外部聯絡範圍。
3. 有真實平台收入和有效分配制度後，再做平台成本與貢獻分配。這個階段不預設建立中央儲值或錢包。

每個切片獨立 PR、限定驗收與交接；既有 Foundation、商務及真人驗收工作線保留。這份規劃不授權合併、部署、切正式旗標或套用新收費。

## 八 四週營運試辦

以下是一個可調整的試辦節奏，所有人數與期限都不是會員資格、強制回流或成效保證。

第一週先邀請願意固定參與的人，聊清楚這一期想完成什麼、卡在哪裡、可投入多少時間。可從約十位核心夥伴、兩三個真實需求的小合作開始；也讓近期少出現的人自願回饋。指定能接住新人的窗口與實際接待範圍。

第二至三週利用原讀書會或固定聚會，加入簡短的成果展示、卡點與媒合。每支小隊只更新主責、下一步與需要的幫助，不增加每日填表。社員可只來學習、參加一次或幫一個小忙。若有適合的夥伴社群，就共同完成一件範圍清楚的事。

第四週核對真正完成與接受的成果，有交易的案件分別確認應付與已付。取得公開同意後整理案例，保留作者、主理人及社群來源；檢視哪種支援有效、哪裡耗費過多協調時間，再定下一期。

Hao 作為方向與營運安排的提案負責人；公會／小隊窗口需自願接受具體範圍，工程修改由相應維護者審查。這份計畫沒有替 Ted 或其他夥伴承諾工時。

| 指標 | 定義與用途 |
| --- | --- |
| 第一次有用參與 | 依入口分開看練習成果、提問得到回覆、參加活動等；閱讀或按鈕點擊不等於已學會 |
