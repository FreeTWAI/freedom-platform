# 群友貢獻的發布途徑

已接受的貢獻，平台要負責給出結束方式；願意貢獻，不代表任何功能都保證進正式主站。
這份文件把「寫完之後怎麼發布」分成三種途徑，三種途徑共用同一套安全底線。
它是協作約定，不是另一套發布系統：沿用現有的獨立 preview build、功能開關與發布程序。

## 合併、部署、開放使用是三件事

- **可以合併**：程式與契約適合進主線。
- **可以部署**：功能關閉或開啟時，都不會破壞現有系統。
- **可以開放使用**：功能本身、設定、資料權限與操作方式已具備。

旗標 OFF 不是免驗證。新增依賴、全域 CSS、CSP、migration 或共用程式，即使畫面沒開也可能影響主站，
照常跑適用檢查。反過來，單純、可隔離的內容或介面改善，不必等物流、付款或可攜平台全部完成才發布。

## 三種途徑

| 途徑 | 適用工作 | 審查與發布 |
| --- | --- | --- |
| 一般改善 | 既有功能的錯誤修正、文案、版面，已接入公會模組內的局部元件 | 對應維護者審查、適用 CI 通過即合併，進下一個小型發布窗口，不等商務大版本。 |
| 限定試用 | 新的公會工具、宣傳圖、Short 等可限制範圍的功能；尚未接會員資料的獨立預覽 | 先完成直接相關的安全與操作驗證，再以指定公會、明確試用範圍或獨立預覽提供，附作者、版本、限制說明與關閉方式。 |
| 核心／交易變更 | 登入、跨租戶授權、付款、庫存、資料遷移與恢復 | 由核心領域維護者整合，驗完整相關流程，再依既有發布程序（migrator、staging→production、健康檢查與收據）啟用；每日備份獨立執行，不是發布前提。 |

獨立預覽也要相稱的檢查：不能使用正式會員 session、正式資料庫、R2 私有資料或正式秘密。
需要後端的預覽使用隔離資料與合成帳號；純前端工具不必為了展示先安裝整個平台。
預覽網址預設任何人都能打開，難猜的網址不等於私密。

## 暫時不能發布時，要有具體答案

每支暫緩的 PR 由維護者留一則摘要，之後更新同一則，不另開追蹤案：

```text
目前卡點：哪個可描述的問題，或缺少哪項驗證
下一棒：作者／領域維護者／CI 維護者／發布者
解除條件：做完什麼就能往前
交付方式：一般改善／限定試用／核心交易變更／明確延後（附原因）
```

「架構尚未完整」「等待整體驗收」「本次不包含」可以是背景，不能是沒有終點的阻塞理由。

## 審查意見分三類

- **必修阻塞**：資料外洩、越權、錯誤或重複寫入、重要功能無法使用、必要檢查缺失，以及合理但尚未排除的重大風險。
  提出時說明它如何破壞本次承諾或安全邊界。
- **平台接線／環境**：fork 沒有必要掃描、Windows 建置、共享 fixture、runner、生成檔、測試資料庫、與 main 的衝突。
  由平台／CI 維護者處理，不要求作者改產品邏輯來「修綠燈」。
- **後續改善**：樣式、命名、重構、更多模板、更多裝置或便利功能。記錄下來，不在最後一輪變成本版條件。

已處理的舊問題不原樣退回。新 head 仍要重新判斷，範圍是新變更與原本約定的完成條件。

## 責任分工

- **作者**：自己功能的正常流程、重要錯誤、資料邊界與使用說明。
- **領域維護者**：相關模組的整合判斷，不把無關的全站完美化追加成條件。
- **平台／CI 維護者**：fork 掃描、Windows 建置、共享 fixture、runner、生成檔及測試資料庫等共同道路。
- **發布者**：主線同步、組合候選、部署、開關、驗收與公告，保留原作者提交與署名。

作者把約定功能與反例修好後，由整合者接手主線同步、必要檢查與發布。
除非發現新的產品問題，不再把環境或流程問題退回作者。
Ted 保留產品取捨、重大風險與費用決策，不是每支 PR 的最後一站。

Fork PR 也會跑 CodeQL：2026-10-20 起 CodeQL 改由 [`.github/workflows/codeql.yml`](../../.github/workflows/codeql.yml)（#914）執行，
fork PR 和同 repo 的 PR 一樣直接取得必要的 CodeQL 結果；第一次貢獻的帳號，workflow 要先由維護者核准才會執行。
head 早於這次切換、或已經和 main 衝突時，由整合者同步 main，或建立保留原作者提交的中央落地分支，作者不必為此重推。

## 小型發布窗口

建議每週安排兩次小型發布窗口，例如週二與週五（台北時間）；實際時段由發布維護者確認並公告。
窗口開始時，已合併且符合條件的工作組成候選；
候選範圍固定，依既有保護完成驗證，不在途中加入無關的新功能。
沒完成的工作留到下一班；一支不相依的 PR 還沒好，不讓其他已完成的工作陪等。
窗口是工作節奏，不保證時間到就無條件上線。

## 範圍調整與結束方式

已接受的工作可以有四種結束方式：完成原範圍、縮成可獨立使用的版本、放到公會限定試用，
或保留為有作者署名的獨立專案。需要調整範圍時，先把原因跟作者講清楚；
不把成果換名後當成中央自己重做的。
