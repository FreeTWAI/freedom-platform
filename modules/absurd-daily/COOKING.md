## CK-4 純狀態與共同操作規則

料理 catalog 與 domain 不依賴 DOM、Three、帳號、儲存或系統時間。所有動作經 `actCooking(run, action, now)`，`advanceCooking` 經同一個單調時鐘；完整 finite/range 檢查、目前 step token、狀態與冷卻在變動前驗證。解析、selector 與讀取不得寫入。

Run v1：穩定本局 id、recipeId、seed、step index、ready/playing/paused/step-result/done、總前景 elapsed、stepElapsed、lastNow、目前 operation state、不可變 step reports。時間單位 ms；座標歸一化 0–1；方向為 left/right/up/down；步驟分數 10–100。無 NaN／Infinity。單次 tick 的烹調模擬積分最多 1,000ms，總前景時間仍按實際間隔計算，上限24小時，避免長幀瞬間燒焦。

一般動作冷卻 120ms；pointer 同一時間只接受一個，拖曳 token 在按下時綁定 step。重入、過期、非 finite、已完成動作不推進、不重複結算。pointercancel／lostcapture取消手勢與 hold；失焦／切背景另自動暫停；恢復必須本人按繼續，背景時間不計分、不烹調。Esc 可暫停。原三款音效維持預設關、本人開啟才播放，離頁釋放；料理場景本批沒有音效。reduced-motion 不影響命中或時間規則。

## CK-5 九種可玩操作

| 操作 | 成功規則與具名參數 | 直接輸入與替代操作 |
| --- | --- | --- |
| 切 slice | 跨過指示線，歸一化距離 >=0.18，方向符合指示；5–8 刀 | pointer 拖刀；空白鍵／按鈕切一刀 |
| 拌 mix | 碗中半徑 0.12–0.48，依指定方向累積角度，2–4 圈；跳點單次最多0.8 rad | 繞圈拖曳；按鈕攪拌一圈 |
| 揉 knead | 3–5 次按住／放開，目標 hold 650–950ms；短於180ms不計 | pointer 或空白鍵按住放開 |
| 煎 pan | 火力在目標 ±14 分，6–9秒積分；進度35–80%翻面一次 | 火力 slider、翻面按鈕／F；低火也可慢慢完成 |
| 煮 boil | 6–9秒積分；撈2次泡沫，泡沫>=18%才可撈；過多泡沫影響品質 | 火力 slider、泡沫按鈕／空白鍵 |

玩法正常失手扣本步品質並有幽默提示，不扣帳號權益。每步有一次明確的開始、操作、完成與下一步。不可用自動計時替代切、拌、揉、折或擺盤的真實輸入。每個步驟本局只結算一次；煎／煮完成須同時滿足火力進度與翻面／撈泡沫要求。

## CK-6 分數與成果

手勢品質與失誤從純 domain 投影；本步品質加權後，每個失誤扣7分，結算clamp至10–100。總分為各步分數算術平均四捨五入；>=85三顆星、>=60兩顆星，其餘一顆星。沒有金錢價值或平台成就。各步報告保留索引、分數、失誤與前景用時；種類與食材沿該recipe固定catalog查詢；重玩不修改舊報告。

結果先產生960×720遊戲料理圖，再沿用既有960×1200 PNG與1200×675站內卡片。長標題／文字須可讀且不溢出。可下載、系統分享、複製同一料理挑戰網址，或保存有界圖片＋文案導向既有 SocialZone 預覽。只有本人按原發布按鈕才發文；取消或儲存失敗保留成果，可重試與下載。分享同料理與分享本次圖有清楚區分。

2026-10-25追加：所有遊戲共用成果分享區，X、Threads、Facebook、Instagram Logo 可點選、亮起並顯示對應操作。X／Threads以文字及公開挑戰連結開啟平台編輯頁；Facebook以公開挑戰網址開啟連結分享頁，文案另行複製。這些入口不會附上本機圖片，畫面明示可下載PNG再附加。Instagram由系統分享選單選App，或下載PNG、複製文案再開啟Instagram；網頁不能預選系統分享目的地，也不宣稱已發布。無API／帳號憑證／自動發文；只有使用者點開入口或系統分享後才離開本頁。取消、剪貼簿拒絕、系統分享不可用時保留成果與手動複製欄位。共用Logo歸屬shared且不載入social-feed／跨平台發文工作引擎。

## CK-7 保存、回復與容量

個人收藏／最佳成績使用 localStorage v1，最多64個recipe條目、64個收藏，<=64KiB；每次變動前讀取當前版本，最佳分數取max，避免舊頁蓋掉較好的成績。相同run id的重複結果不新增紀錄。備份只保留上一份可解析的版本；損毀 primary 不覆蓋良好 backup。拒絕未知版本、非finite數字、未知料理及超量資料；讀取不修寫。

目前run保存在同分頁 sessionStorage，最近一盤保留7天，避免別的分頁接管正在做的料理。預覽別道料理不覆蓋現有進度；開始新菜色才替換，畫面說明此限制。動作及tick保存最多每750ms一次，結算／下一步／暫停／離頁立即保存。重新整理後顯示已暫停的原進度，由本人選擇繼續或重新開始；不把離線間隔算進clock或火候。寫入失敗不宣稱成功，記憶體內仍可玩，提供重試。個人本機保存不宣稱跨裝置同步；只刪本模組自己的key，重玩有確認。

關閉遊戲、重試、切菜色清 RAF、pointer、listener、音效和待辦回呼；異步圖片／分享完成必須核對run id與generation。控制項不得被舊局或舊圖片回覆重新啟用。

## CK-8 驗證與界線

1. catalog：64唯一id／64唯一圖格／8×8分類，3–4步，每種操作有代表；JSON可序列化，檔案、尺寸、比例與壓縮容量可核對。
2. domain：9操作全鏈成功、錯方向／半徑／時間、重入／舊step、paused不動、長幀、煎翻面與撈泡沫、烤過頭可結束、每步與全局只結算一次；實際可從64道start走到result。
3. storage：fresh、roundtrip、過期／損毀／未來版本、backup回復、quota／denied、重複結果、fresh max合併；讀取零寫入。
4. production build 後的真實 UI：代表9種操作的pointer／鍵盤完整旅程；分類搜尋收藏、完成與reload接續、未知料理、拒絕儲存、分享不自動POST、登入接續；原8個arcade案例相容。
5. 手機320、390、667×375橫向、平板768、桌面1440；100/125/200%文字，長真實菜名、空結果、loading/error、暫停、成果；截圖、console與實際hit-box檢查，圖片缺少時仍可用。
6. Node24型別、標準build、module/context、inventory與diff檢查，按新head跑必要CI／獨立審查。PR #1033正在修原遊戲的startup同步測試，避免重寫或放寬其待合併案例。

自動化／開發者試玩不等於真人覺得好玩。真實 iPhone／Android、真人美術／手感／留存仍 EXTERNAL_PENDING；本任務不授權merge、deploy、通知外部人員或付費模型服務。
