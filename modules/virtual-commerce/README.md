# 虛擬導購工作台 — 第一階段文字彩排

獨立於既有商店與私人 AI 頁面，沿用已登入 portal。單一操作員、單一合成供應商、最多五項測試商品、一個模擬留言來源；沒有實際供應商或創作者身分認證。

## 已實作範圍

本頁記憶體中的商品來源、期限及遞增版本 → 主講草稿／有限模板短答 → 操作員逐段確認 → 同一文字排程 → 手動完成段落／下一段。每次最多一個 active cue；最多連續兩個短答後回到主講。留言只觸發有限商品問句的待確認短答，不解析控制指令、不送模型、不把原留言插入講稿。

資料更新立即取消正在準備／顯示的段落，刪除該商品佇列並保守清空整份快取。聲線、語速、人物版本變更清除全部佇列／快取。快取綁完整商品事實、來源、版本、期限、文字與設定；只保存文字彩排產物，絕不是語音或嘴型。最多50段／50份快取，最多200個留言事件去重。商品有效期限最多30分鐘，短答60秒；每次排程前及非同步回傳後都重驗。

暫停／人工接管取消目前段落與 in-flight 準備；重新開始時從段首確認，不假稱可恢復音訊播放位置。停止清空佇列和快取；需明確「重新開始彩排」才解除。切頁、登出、重新整理丟棄全部內容，帳號與 session generation 用 React key 隔離。這不是可保存的正式工作台。

## 權限與未配置

操作員是本機 UI 可信輸入端，不是伺服器授權。`receiveViewer` 是唯一不可信留言入口；未實作外部 webhook。不得把 operator 方法暴露給 viewer adapter。

**Google TTS、voice/avatar license、嘴型、直播帳號、push、成本批准、live catalog 均 NOT_CONFIGURED。** 這版只提供可執行的文字彩排，不產生假音訊、不模擬推流成功。正式 provider 需另經資料出口／費用／素材授權／帳號驗證，不得直接用此 preview provider 推流。

既有商店讀取有 tenant/session 與 store 權限；公開 publication 是歷史快照，不是即時庫存與價格權威。這版刻意不連真商品，避免把未重新確認的資料變成交易承諾。沒有 migration、API、資料庫、storage、付款、訂單或正式資料寫入。

## 驗證與後續

`tests/runtime/virtual-commerce.test.ts` 驗證版本與期限失效、唯一排程、人工介入、舊 promise、快取完整 binding、留言隔離及上限。UI 需真實瀏覽器流程驗證；純 state/hook tests 不等於畫面或完整直播驗收。

下一階段先接既有授權 catalog read＋播前重驗，再於使用者批准成本與合法素材後做真正 TTS／嘴型／平台 adapter；不可把本版的文字狀態直接宣稱生產 ready。
